## 1. 背景与目标

## 3. 设计

### 3.1 架构

- 新增 `packages/cli/src/compaction-config.ts`：`createCompactionConfig` helper 集中构造四字段
- `buildHarness`（repl.ts）+ `runPrintMode`（print-mode.ts）各自调用 helper 注入
- harness 小改（非 breaking）：`maybeCompact` 加 try/catch + 接 signal + emit 失败事件
- compaction 小改（向后兼容）：`CompactionContext` 加 `signal?`、`CompactDeps.generateSummary` 签名加可选 `signal`
- shared 小改：`HarnessCustomEvent` union 加 `CompactionErrorEvent`
- rpc 小改：`serializeEvent` 加 `compaction_error` case
- 三 mode 一致接通

### 3.2 组件

**`createCompactionConfig(opts: { provider, model, getApiKey, stageMarkers? })`** → `{ compactor, compactorDeps, modelContextWindow, budgetThresholds }`

```
const model = getModel(provider, model)               // 构造期同步调，失败早于 prompt（与 harness :129 一致）
modelContextWindow = model.contextWindow
compactor          = createCompactor({ stageMarkers: opts.stageMarkers ?? [] })
compactorDeps      = { generateSummary: createSummaryGenerator(model, getApiKey, provider) }
budgetThresholds   = DEFAULT_THRESHOLDS
```

**`createSummaryGenerator(model, getApiKey, provider)`** → `(messages: AgentMessage[], signal?: AbortSignal) => Promise<string>`

```
const apiKey = await getApiKey(provider)              // await：getApiKey 可异步（harness.ts:45）
const assistant = await completeSimple(model, {
  systemPrompt: SUMMARIZE_PROMPT,
  messages,
}, { apiKey, signal })                                 // 透传 signal，支持 abort
return 取 assistant.content 的 text block（无 text 则空串）
```

**`SUMMARIZE_PROMPT`**（草案，质量留待 Slice 4 instinct / 人工评估；本 slice 只验「调 completeSimple 且返回非空 text」）：
> Summarize the preceding conversation history concisely for context retention. Preserve: key decisions and their rationale, files read/written/edited (with paths), important errors encountered and resolutions, and any unfinished tasks. Omit verbatim tool-call arguments and large file contents. Output only the summary prose.

### 3.3 数据流

每个 `prompt` turn 完成（assistant 回复已生成落盘）后：
1. `maybeCompact(signal)`（若 compactor + compactorDeps）→ `buildCompactionContext`（tokenThreshold=100000 默认，透传 signal）→ `shouldCompact` → `compact` → `generateSummary`（completeSimple，honor signal）→ 落盘 `CompactionEntry` → emit `compaction` 事件 → `messages = [summaryMessage, ...keptMessages]`
2. `maybeAuditBudget`（若 modelContextWindow）→ `audit` → emit `context_budget`（有 suggestions 或 total > window）
3. rpc mode：`serializeEvent` 推 `compaction`/`context_budget`/`compaction_error` 事件给 client
4. `--resume`：`rebuildMessages` 遇 `CompactionEntry` 注入 summary（Slice 1 issue #3 已修）

### 3.4 错误处理

**`maybeCompact` 加 try/catch（选项 3，红队 blocking #1 修订）**：
- try/catch 包**整个 `maybeCompact` 方法体**（`compact → appendEntry → emit compaction → 替换 messages`），任何中间步骤抛错 → catch
- catch 内：若 error 是 `AbortError`（signal aborted）→ **不 emit compaction_error**（abort 非治理失败），直接 return；否则 emit `compaction_error` 事件（payload `{ error: message }`），**不 rethrow**，messages 保持原样
- **非原子不变量**（既存 Slice 1 风险，本 slice 不消除但记录）：若 `appendEntry`（落盘）成功后、`emit compaction`/`替换 messages` 抛错，CompactionEntry 已落盘但内存 messages 未替换——`--resume` 重建注入 summary 可修复一致性，可接受。try/catch 包整个方法体确保此类中间抛错也归入 compaction_error 而非冒泡中断 prompt
- 下个 turn `maybeCompact` 再试；持续失败则历史膨胀直至 LLM 真超 contextWindow——该错误属 LLM 调用失败，正常冒泡（合理，另一层）；`maybeAuditBudget` 的 `context_budget` 事件是该失败模式唯一可见信号
- `compaction_error` 事件落点：`shared/src/index.ts` `HarnessCustomEvent` union 加 `CompactionErrorEvent { type: "compaction_error"; error: string }`；`rpc.ts` `serializeEvent` 加 `case "compaction_error"` 透传 `{ error }`
- 不采用「静默吞」——compaction 有副作用（替换 messages + 落盘），失败是治理失效必须可见；不采用「冒泡」——compaction 是 turn 后处理（回复已落盘），冒泡会让调用方误判 turn 失败致状态不一致

**abort 语义（红队 important #4）**：`generateSummary` 接收 `signal`（经 `CompactionContext.signal?` ← `maybeCompact(signal)` ← `prompt(input, signal)` 透传），completeSimple honor signal。RPC timeout 软中止若卡在 compaction 的 completeSimple 期间，可中止该 LLM 调用（避免 timeout 已 emit 但后台 LLM 仍烧钱）。AbortError 不 emit compaction_error。

**`getModel` 抛错**（自定义 provider/model 不在注册表）：`createCompactionConfig` 构造期同步调 `getModel`，失败早于 prompt（与 harness `:129` 同次序），cli 不额外处理。

### 3.5 接通范围（用户选 A）

三 mode 全接通：print/repl/rpc 都传四字段。
- print 单 turn：`maybeCompact` 历史短 → `shouldCompact=false`，compaction 实际不触发（无害）；`maybeAuditBudget` 每 turn 跑，有 budget 诊断价值
- B 的真对话 compaction 触发验证靠 repl/rpc 多 turn

### 3.6 默认决策

1. `compactionTokenThreshold`：用 harness 默认 100000，不暴露 cli flag（YAGNI）
2. `stageMarkers`：默认空（token 阈值为主），不暴露 flag
3. `budgetThresholds`：`DEFAULT_THRESHOLDS`，不暴露 flag
4. Slice 1 待校准项 #1（token 阈值 vs ARCH §4.2「阶段边界触发」）：本 slice 不校准，记 ADR defer（`stageMarkers` 已提供阶段边界能力，默认空；真阶段检测远期复用 Audit §4.9 模式识别）

## 6. 不做（YAGNI / defer）

- cli flag 暴露 compaction/budget 参数（默认值足够，YAGNI）
- 真阶段检测（defer 远期 Audit）
- ContextBudget memory 组件（Slice 4 instinct 才建）
- print 模式 compaction 触发（单 turn 不触发，设计如此）
- **双 LLM 调用成本降级**（红队 important #3，advisory）：每次 `shouldCompact` 命中产生一次额外 completeSimple round-trip（同 model 整段被压缩历史），长会话频繁触发是真实开销。本 slice 不降级，未来可让 generateSummary 用更便宜 model 或降级到截断（无 LLM）策略
